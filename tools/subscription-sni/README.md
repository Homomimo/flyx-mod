# 订阅流量统计：按时段查看访问 SNI

面板管理端 → 订阅 → 点开一条分享订阅 → 流量统计。点选趋势图或「查看时段」可切换小时、日期、月份。SNI 统计独立于计费；不影响上下行字节。没有数据时不会用 DNS、代理目标或示例数据填充。演示站（`VITE_DEMO=true`）使用 `.test` 假域名。

## 启用一个自建节点（Linux，可选）

1. 更新面板前后端及对应节点的 Agent。仅有旧 Agent 或节点不在线时页面会说明不可用，而不会当作零次访问。
2. 仅为已获授权的订阅启用。节点需已具备 FLYX 按订阅设置出站 socket mark 的条件；需要支持 `@ih` 和 NFLOG 的 Linux 内核和 nftables，以及 Python 3、libnetfilter_log 和 SQLite CLI（带 JSON 函数）。Debian 节点的依赖包为 `nftables python3 libnetfilter-log1 sqlite3`。本功能不会自动安装组件或抓取所有网卡。
3. 在节点本机，从源码根目录启动，例如 `sudo python3 tools/subscription-sni/collector.py 7 12`，其中 **7、12 换成订阅 ID**（不是入站、节点或用户 ID）。没有列出的订阅不采集。首次建议前台启动，确认没有权限或 nft 语法错误，再从该订阅向已知 HTTPS 测试域名发起一次新的 TCP 握手；默认面板约每 30 秒刷新。旧记录不能补采。
4. Ctrl+C 停止并清理本工具专用的 `inet flyx_sni_optin` 表，不改 FLYX 现有表和转发策略。若进程被强杀，确认服务未运行且表确属本工具后，可用 `sudo nft delete table inet flyx_sni_optin` 清理残留表再启动。Docker Agent：采集器应在能看到相同内核出站流量的主机网络命名空间运行，且将主机 `/var/lib/flyx-sni` 目录只读挂载到 Agent 容器同路径（包括 SQLite WAL / SHM 文件）。不需要在容器运行第二个采集器。

## 数据边界

- 只观察已选订阅标记的出站 TCP/443 中可以在单个报文（最多 8192 字节）解析的 TLS ClientHello。分片、跨包、大握手、QUIC/UDP、未保留标记的中继及导入节点可能无结果；ECH 不能还原内层域名。握手不是访问成功的证明。
- 原始报文只经过内存；节点库只写入订阅 ID、分钟、域名、次数及采集器心跳。没有 IP、URL、路径、报文文件，不把浏览历史复制到面板数据库。按当前订阅所属的自建节点只读查询，离线/移出订阅的节点不会贡献历史结果；停止采集、但 Agent 在线时仍可查保留期内的记录。
- 默认只展示最近 30 天的样本，按月查看也不会延长保留期。采集器运行时清理超过 30 天的记录；停用后若要立即清除，先停止采集器，再由节点管理员清理专用数据目录。节点磁盘应受保护，避免跨面板或重置订阅 ID 后继续复用同一份库。
- 同一订阅、同一 ClientHello 随机值短时去重。每订阅每秒最多观察约 100 个样本、每分钟最多 256 个域名，数据量过大时可能少计。每节点最多返回 100 个域名；发生截断时面板提示不完整。数据库限制 131072 页（默认页大小时约 512 MiB，不含 WAL）；写满将停止而不是无限扩张。

## 自测

`python3 -B -m unittest discover -s tools/subscription-sni` 测试真实 TLS ClientHello 解析、不带 SNI、订阅隔离、跨分钟及重传去重。生产启用前还需在实际 Linux 节点验证网络命名空间、socket mark、nft 和 NFLOG 权限。
